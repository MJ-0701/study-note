## 선행개념 정리

### 개념: LAN과 IEEE 802 데이터링크 계층

- LAN은 한 건물, 학교, 기관처럼 좁은 범위 안의 장치들을 연결하는 근거리 통신망이다.
- LAN의 핵심 특징은 짧은 거리, 빠른 전송속도, 낮은 오류율, 쉬운 설치/확장, 기관 자체 관리다.
- IEEE 802에서는 데이터링크 계층을 LLC와 MAC으로 나누어 설명한다.
- LLC는 상위 네트워크 계층과의 인터페이스, 흐름제어, 오류제어, 순서제어를 맡는다.
- MAC은 공유 매체 접근 제어, MAC 주소 처리, 프레임 생성, FCS 오류 검출을 맡는다.

### 개념: 매체 접근 제어

- 여러 장치가 같은 전송매체를 공유하면 누가 언제 보낼지 정해야 한다.
- CSMA/CD는 유선 이더넷에서 충돌을 감지하는 방식이다.
- 토큰링과 토큰버스는 토큰을 가진 장치만 전송하게 해서 충돌을 없애는 방식이다.
- 무선랜은 송신 중 충돌 감지가 어려워 CSMA/CA로 충돌을 피한다.
- 시험에서는 `CSMA/CD = 충돌 검출`, `CSMA/CA = 충돌 회피`를 가장 먼저 떠올리면 된다.

### 개념: 이더넷과 무선랜 프레임

- 이더넷 프레임은 목적지 MAC, 출발지 MAC, 길이/타입, 데이터, FCS를 포함한다.
- Preamble과 SFD는 수신 동기와 프레임 시작 표시용이다.
- 무선랜 MAC 프레임은 AP와 분배 시스템을 거칠 수 있어 주소 필드가 최대 4개까지 있다.
- FCS는 프레임 오류 검출용 필드다.

### 개념: 네트워크 장비와 OSI 계층

- 리피터와 허브는 1계층 물리계층 장비다. 신호/비트만 본다.
- 브리지와 스위치는 2계층 데이터링크 계층 장비다. MAC 주소와 프레임을 본다.
- 라우터는 3계층 네트워크 계층 장비다. IP 주소와 패킷을 본다.
- 게이트웨이는 상위 계층까지 포함해 서로 다른 프로토콜을 변환한다.
- 계층이 올라갈수록 더 많은 정보를 해석한다.

### 개념: 회선교환과 패킷교환

- 회선교환은 통신 전에 전용 경로를 설정한다. 전화망처럼 순서와 지연이 안정적이다.
- 데이터그램 방식은 패킷마다 독립적으로 경로를 정한다. IP 방식과 연결된다.
- 가상회선 방식은 통신 전에 논리 경로를 설정하고 그 경로로 순서대로 보낸다.
- 시험 답안은 `경로 설정 여부`, `순서 보장 여부`, `효율`, `지연`, `장단점`으로 비교하면 된다.

### 개념: TCP/IP 계층 구조

- OSI는 7계층 이론 모델이고, TCP/IP는 인터넷에서 실제 사용하는 4계층 모델이다.
- TCP/IP 응용 계층은 OSI의 응용/표현/세션 계층에 대응한다.
- TCP/IP 전송 계층은 TCP와 UDP가 핵심이다.
- TCP/IP IP 계층은 IP, ICMP, IGMP, 라우팅 프로토콜, ARP/RARP와 연결된다.
- 네트워크 액세스 계층은 물리/데이터링크 계층 기능을 담당한다.

### 개념: 인터넷 주소 3가지

- MAC 주소는 데이터링크 계층 주소이고 NIC에 저장된다.
- IP 주소는 네트워크 계층 논리 주소이고 OS 네트워크 설정에 저장된다.
- 호스트 이름/도메인 이름은 응용 계층에서 사람이 쓰기 쉬운 문자 이름이고 DNS가 IP로 바꾼다.
- 시험에서는 `계층`, `저장 위치`, `역할`을 세트로 써야 한다.

### 개념: IP 헤더와 단편화

- IPv4 헤더는 32비트 단위로 그리면 외우기 쉽다.
- Version, Header Length, Service Type, Total Length가 첫 줄이다.
- Identification, Flags, Fragment Offset은 단편화와 재조립에 쓰인다.
- TTL은 라우터를 지날 때마다 줄어 0이면 폐기된다.
- Protocol은 상위 프로토콜을 알려준다. TCP=6, UDP=17, ICMP=1.

### 개념: TCP 헤더와 신뢰성

- TCP는 연결형, 신뢰성, 순서 보장, 흐름제어, 오류제어가 핵심이다.
- 순서 번호는 보낸 데이터의 순서를 나타낸다.
- 확인응답 번호는 다음에 받을 바이트 번호를 뜻한다.
- 윈도우 크기는 수신측 버퍼 기준의 흐름제어에 쓰인다.
- 코드 비트 U, A, P, R, S, F는 긴급/ACK/Push/Reset/SYN/FIN이다.

### 개념: ARP, RARP, DNS

- ARP는 IP 주소를 MAC 주소로 바꾼다.
- RARP는 MAC 주소를 IP 주소로 바꾼다.
- DNS는 도메인 이름을 IP 주소로 바꾼다.
- ARP/RARP는 같은 LAN 안의 주소 해석, DNS는 인터넷 이름 해석으로 구분한다.

### 개념: IPv6와 라우팅 프로토콜

- IPv6의 핵심은 128비트 주소, 헤더 단순화, 보안, QoS, 자동 구성이다.
- RIP는 거리 벡터 방식이고 홉 수를 기준으로 한다.
- OSPF는 링크 상태 방식이고 비용을 기준으로 한다.
- 작은 네트워크는 RIP, 큰 네트워크는 OSPF가 적합하다고 정리하면 된다.

## I. 설명형 문항

### 1. LAN의 정의 및 특징, MAC 계층과 LLC 계층의 기능

**시험 답안**

LAN은 건물, 학교, 회사처럼 제한된 지역 안의 컴퓨터, 단말, 주변기기를 연결하여 데이터와 자원을 공유하는 근거리 통신망이다. 보통 한 기관이 직접 소유하고 관리한다.

LAN의 특징은 전송 거리가 짧고, 전송 속도가 빠르며, 오류율이 낮고, 설치와 확장이 비교적 쉽다는 점이다. 또한 여러 장치가 전송매체를 공유할 수 있으므로 매체 접근 제어가 필요하다.

IEEE 802에서는 데이터링크 계층을 LLC와 MAC으로 나눈다. LLC는 상위 네트워크 계층과의 인터페이스 역할을 하며 흐름제어, 오류제어, 순서제어를 담당한다. MAC은 공유 매체를 누가 사용할지 정하는 접근 제어 기능을 담당하고, MAC 주소 처리, 프레임 생성, FCS를 통한 오류 검출을 수행한다.

**해설**

이 문제는 LAN 정의만 쓰면 부족하다. 반드시 `LAN 특징 -> LLC 기능 -> MAC 기능` 순서로 써야 한다. LLC는 상위 계층과 연결되는 공통 부분이고, MAC은 실제 매체에 접근하는 규칙이다. CSMA/CD나 토큰 패싱은 MAC 계층 예시로 넣으면 답안이 선명해진다.

### 2. LAN 토폴로지 5개

**시험 답안**

토폴로지는 네트워크 장치들의 연결 형태를 뜻한다.

| 토폴로지 | 설명 | 장단점 포인트 |
|---|---|---|
| 성형 Star | 중앙 허브/스위치에 각 노드를 1:1로 연결 | 한 노드 고장은 영향이 작지만 중앙 장치 고장 시 전체 장애 |
| 버스형 Bus | 하나의 공통 케이블에 모든 노드를 연결 | 단순하고 저렴하지만 케이블 장애 시 전체 영향 |
| 링형 Ring | 노드를 고리 모양으로 연결하고 신호/토큰이 순환 | 순서 보장, 한 곳 장애 시 전체 영향 가능 |
| 트리형 Tree | 성형 구조를 계층적으로 확장 | 확장 쉬움, 상위 노드 장애 시 하위 구간 단절 |
| 망형 Mesh | 노드들을 그물처럼 다중 경로로 직접 연결 | 신뢰성 높음, 비용과 배선 복잡도 큼 |

**해설**

객관식으로 나오면 `중앙 장치`, `공통 케이블`, `고리`, `계층`, `그물` 키워드를 보고 맞추면 된다. 주관식이면 각 형태마다 장점/단점 한 개씩만 붙여도 충분하다.

### 3. CSMA/CD 특징, 동작원리, 이더넷 프레임 구조

**시험 답안**

CSMA/CD는 Carrier Sense Multiple Access with Collision Detection의 약자로, 유선 이더넷 IEEE 802.3에서 사용하는 매체 접근 방식이다. 전송 전에 매체가 비어 있는지 감지하고, 여러 장치가 동시에 전송해 충돌이 발생하면 이를 검출한 뒤 재전송한다.

동작 순서는 다음과 같다.

1. 보낼 데이터가 있으면 매체가 사용 중인지 확인한다.
2. 매체가 비어 있으면 전송하고, 사용 중이면 기다린다.
3. 전송 중에도 충돌 여부를 계속 감지한다.
4. 충돌이 감지되면 전송을 멈추고 Jam 신호를 보낸다.
5. 임의의 백오프 시간을 기다린 후 다시 전송을 시도한다.

이더넷 프레임 구조는 다음과 같다.

`Preamble(7) | SFD(1) | Destination MAC(6) | Source MAC(6) | Length/Type(2) | Data(46~1500) | FCS(4)`

**해설**

CSMA/CD는 `듣고 -> 비면 보내고 -> 충돌 나면 멈추고 -> 랜덤 대기 후 재전송`으로 외운다. 프레임 구조는 byte 수까지 묻는 빈칸형으로 나올 수 있으므로 `7,1,6,6,2,46~1500,4` 순서가 중요하다.

### 4. 토큰링과 토큰버스

**시험 답안**

토큰링과 토큰버스는 모두 토큰 패싱 방식이다. 토큰을 가진 노드만 데이터를 전송할 수 있으므로 충돌이 발생하지 않는다.

토큰링 IEEE 802.5는 물리적 또는 논리적으로 링 구조를 이루며, 토큰이 링을 따라 순환한다. 토큰을 받은 노드가 데이터를 전송하고, 전송 후 토큰을 다음 노드로 넘긴다. 순서가 보장되고 부하가 높아도 안정적이다.

토큰버스 IEEE 802.4는 물리적으로는 버스 구조지만 논리적으로는 링처럼 노드 순서를 정해 토큰을 전달한다. 우선순위 제어와 실시간 전송에 유리하여 공장 자동화 등에 사용된다.

**해설**

둘의 공통점은 `토큰이 있어야 전송`, 차이점은 `토큰링은 링`, `토큰버스는 물리 버스/논리 링`이다. 객관식에서 “충돌이 없다”가 나오면 토큰 방식과 연결한다.

### 5. 10BASE-T, 10BASE5, 10BASE-F 의미

**시험 답안**

이더넷 규격 이름은 `[속도][전송방식][매체 또는 거리]`를 뜻한다. `10`은 10Mbps, `BASE`는 베이스밴드 전송을 뜻한다.

| 규격 | 의미 |
|---|---|
| 10BASE5 | 10Mbps, 베이스밴드, 최대 500m, 굵은 동축케이블 |
| 10BASE2 | 10Mbps, 베이스밴드, 약 185m, 가는 동축케이블 |
| 10BASE-T | 10Mbps, 베이스밴드, UTP 꼬임선, 허브 중심 성형, 약 100m |
| 10BASE-F | 10Mbps, 베이스밴드, 광섬유 |

**해설**

숫자가 뒤에 오면 대체로 거리 단서이고, 문자가 오면 매체 단서다. `T = Twisted Pair`, `F = Fiber`로 외우면 된다.

### 6. 무선랜 IEEE 802.11

**시험 답안**

BSS는 AP 하나와 그 AP에 연결된 단말들의 집합으로 무선랜의 기본 단위이다. ESS는 여러 BSS를 분배 시스템으로 연결한 확장 무선망이며 AP 간 로밍이 가능하다. 애드혹 또는 IBSS는 AP 없이 단말끼리 직접 연결하는 임시 무선망이다.

물리층 기술에는 FHSS, DSSS, IR, OFDM이 있다. FHSS는 주파수를 일정 패턴으로 바꾸며 전송해 간섭에 강하다. DSSS는 데이터를 칩 코드로 확산해 넓은 대역으로 전송한다. IR은 적외선으로 근거리 전송한다. OFDM은 여러 직교 부반송파에 데이터를 나누어 고속 전송에 유리하다.

CSMA/CA는 무선에서 충돌을 직접 감지하기 어렵기 때문에 충돌을 미리 피하는 방식이다. 매체가 비어도 IFS를 기다리고 백오프 후 전송하며, 수신측 ACK로 성공 여부를 확인한다. 필요하면 RTS/CTS를 사용한다.

숨겨진 터미널 문제는 서로 감지하지 못하는 두 단말이 같은 AP로 동시에 전송해 AP에서 충돌이 생기는 문제다. RTS/CTS로 매체를 예약하여 해결할 수 있다.

무선랜 MAC 프레임 구조는 `Frame Control | Duration/ID | Address 1~4 | Sequence Control | Frame Body | FCS`이다. 무선은 AP와 분배 시스템을 거칠 수 있어 주소 필드가 최대 4개까지 있다.

**해설**

이 문제는 긴 문항이라 네 덩어리로 나눠 외워야 한다. `BSS/ESS/Ad-hoc`, `물리층 4개`, `CSMA/CA와 숨겨진 터미널`, `MAC 프레임` 순서다. 객관식이면 FHSS/DSSS/OFDM 특징 구분과 RTS/CTS 역할이 자주 걸린다.

### 7. 트랜시버, 리피터, 허브, 브리지, 스위치, 라우터, 게이트웨이

**시험 답안**

| 장비 | 계층 | 설명 |
|---|---|---|
| 트랜시버 | 물리 | 신호를 송수신하는 장치 |
| 리피터 | 물리 | 약해진 신호를 증폭/재생해 전송 거리를 늘림 |
| 허브 | 물리 | 포트가 여러 개인 리피터, 들어온 신호를 모든 포트로 전달 |
| 브리지 | 데이터링크 | MAC 주소를 보고 LAN을 연결/분리하고 충돌 영역을 나눔 |
| 스위치 | 데이터링크 | 포트가 많은 고속 브리지, MAC 주소표로 해당 포트에만 전달 |
| 라우터 | 네트워크 | IP 주소를 보고 서로 다른 네트워크 사이의 경로를 결정 |
| 게이트웨이 | 상위 계층 | 서로 다른 프로토콜의 망을 연결하고 변환 |

**해설**

이 문항은 장비 이름과 OSI 계층을 같이 외우는 것이 핵심이다. `허브까지는 물리`, `브리지/스위치는 MAC`, `라우터는 IP`, `게이트웨이는 변환`으로 정리한다.

### 8. 리피터, 브리지, 라우터, 게이트웨이와 OSI 7계층

**시험 답안**

리피터는 1계층 물리계층 장비로 비트 신호를 재생한다. 브리지는 2계층 데이터링크 계층 장비로 MAC 주소와 프레임을 보고 전달 여부를 결정한다. 라우터는 3계층 네트워크 계층 장비로 IP 주소와 패킷을 보고 경로를 선택한다. 게이트웨이는 4~7계층 상위 계층까지 포함해 서로 다른 프로토콜을 변환한다.

**해설**

문장형으로 쓰면 `계층 -> 보는 정보 -> 역할` 순서가 좋다. 예를 들어 라우터는 “3계층에서 IP 주소를 보고 패킷을 전달한다”처럼 쓰면 깔끔하다.

### 9. 브리지와 스위치 비교

**시험 답안**

브리지와 스위치는 모두 데이터링크 계층에서 동작하며 MAC 주소를 보고 프레임을 전달하고 충돌 영역을 나눈다. 스위치는 포트가 많고 빠른 브리지라고 볼 수 있다.

| 구분 | 브리지 | 스위치 |
|---|---|---|
| 포트 수 | 적음 | 많음 |
| 처리 방식 | 소프트웨어 처리 비중 큼 | ASIC 등 하드웨어 기반 고속 처리 |
| 속도 | 느린 편 | 빠름 |
| 충돌 영역 | 세그먼트 분리 | 포트마다 충돌 영역 분리 |
| 용도 | 예전 LAN 분할 | 현대 LAN 기본 장비 |

**해설**

주관식은 공통점과 차이점을 모두 써야 점수가 안정적이다. 첫 문장에 공통점을 쓰고, 표나 문장으로 포트 수/속도/충돌 영역을 비교한다.

### 10. 회선교환망과 패킷교환망 비교

**시험 답안**

회선교환은 통신 전에 전용 경로를 설정하고 통신이 끝날 때까지 그 경로를 독점한다. 순서가 보장되고 지연이 안정적이어서 전화망에 적합하지만, 사용하지 않는 시간에도 회선을 차지하므로 효율이 낮다.

패킷교환의 데이터그램 방식은 연결을 미리 설정하지 않고 패킷마다 독립적으로 경로를 선택한다. IP가 대표적이다. 회선 효율이 높고 장애에 강하지만 패킷 순서가 바뀔 수 있고 지연이 일정하지 않다.

패킷교환의 가상회선 방식은 통신 전에 논리적인 경로를 설정한 후 그 경로로 패킷을 순서대로 전송한다. X.25, 프레임 릴레이, ATM과 연결된다. 순서 보장과 효율을 절충하지만 경로 설정 부담이 있고 설정 경로 장애에 약하다.

**해설**

비교 기준은 `경로를 미리 잡는가`, `전용인가 공유인가`, `순서가 보장되는가`, `효율과 지연이 어떤가`다. 시험장에서 시간이 없으면 “회선=전용/안정/비효율, 데이터그램=비연결/효율/순서불안, 가상회선=논리연결/순서/설정부담”으로 압축한다.

### 11. OSI 참조모델과 TCP/IP 비교, TCP/IP 계층별 프로토콜

**시험 답안**

OSI 참조모델은 통신 기능을 7계층으로 나눈 이론적 모델이고, TCP/IP는 인터넷에서 실제 사용하는 4계층 프로토콜 체계이다.

| OSI 7계층 | TCP/IP 4계층 |
|---|---|
| 응용, 표현, 세션 | 응용 계층 |
| 전송 | 전송 계층 |
| 네트워크 | IP 계층 |
| 데이터링크, 물리 | 네트워크 액세스 계층 |

TCP/IP 계층별 대표 프로토콜:

| TCP/IP 계층 | 대표 프로토콜 |
|---|---|
| 응용 계층 | HTTP, FTP, TELNET, SMTP, DNS, SNMP, Ping |
| 전송 계층 | TCP, UDP |
| IP 계층 | IP, ICMP, IGMP, OSPF, RIP, ARP, RARP |
| 네트워크 액세스 계층 | Ethernet, LAN 관련 프로토콜 |

ARP와 RARP는 IP 주소와 MAC 주소를 연결하므로 IP 계층과 네트워크 액세스 계층 사이에 걸쳐 있다고 설명할 수 있다.

**해설**

이 문제는 그림 8-2, 8-3을 요구하므로 표를 그대로 그릴 수 있어야 한다. 핵심은 OSI의 상위 3계층이 TCP/IP 응용 계층으로 합쳐지고, OSI의 하위 2계층이 네트워크 액세스 계층으로 합쳐진다는 점이다.

### 12. 인터넷 사용에 필요한 주소 3가지

**시험 답안**

| 주소 | 계층 | 저장 위치 | 역할 |
|---|---|---|---|
| MAC 주소 | 데이터링크 계층 | NIC에 제조 시 저장, 48비트 | 같은 LAN 안에서 장치 구분 |
| IP 주소 | 네트워크 계층 | OS 네트워크 설정, 변경 가능 | 인터넷에서 목적지까지 패킷 전달 |
| 호스트 이름/도메인 이름 | 응용 계층 | DNS 서버 또는 hosts 파일 | 사람이 읽기 쉬운 이름을 IP로 변환 |

**해설**

이 문항은 괄호에 `어느 계층`, `어디 저장`, `역할`이라고 되어 있으므로 이 세 칸을 빠뜨리면 안 된다. 도메인 이름 예시는 `unicorn.soongsil.ac.kr`처럼 쓰면 좋다.

### 13. IP 주소 체계 클래스 분류

**시험 답안**

IPv4 주소는 32비트이고 8비트씩 네 부분으로 나누어 점 십진 표기한다. 앞부분은 네트워크 식별자, 뒷부분은 호스트 식별자이며 시작 비트에 따라 클래스를 나눈다.

| 클래스 | 시작 비트 | 주소 범위 | 용도 |
|---|---|---|---|
| A | 0 | 0.0.0.0 ~ 127.255.255.255 | 대규모 네트워크 |
| B | 10 | 128.0.0.0 ~ 191.255.255.255 | 중규모 네트워크 |
| C | 110 | 192.0.0.0 ~ 223.255.255.255 | 소규모 네트워크 |
| D | 1110 | 224.0.0.0 ~ 239.255.255.255 | 멀티캐스트 |
| E | 1111 | 240.0.0.0 ~ 255.255.255.255 | 연구/예약 |

추가로 127.x.x.x는 루프백 주소이고, 10.x.x.x, 172.16~31.x.x, 192.168.x.x는 사설 IP 주소다.

**해설**

범위 포함 주관식이라 첫 옥텟 범위를 외우는 게 핵심이다. 실무 기준으로는 A 클래스에서 0과 127은 특수 용도로 빠지는 식의 세부가 있지만, 레포트 답안 기준 표를 우선 외우면 된다.

### 14. TCP와 UDP 특징

**시험 답안**

| 구분 | TCP | UDP |
|---|---|---|
| 연결 | 연결형, 3-way handshake | 비연결형 |
| 신뢰성 | ACK와 재전송으로 보장 | 보장하지 않음 |
| 순서 | 순서 번호로 보장 | 순서가 바뀔 수 있음 |
| 흐름/오류 제어 | 있음 | 없음 |
| 헤더 | 20바이트 이상 | 8바이트 |
| 속도 | 상대적으로 느리고 무거움 | 빠르고 가벼움 |
| 용도 | 웹, 메일, 파일 전송 | 스트리밍, DNS, 게임 |

**해설**

TCP는 정확성, UDP는 속도다. `TCP=연결형/신뢰성/순서/제어`, `UDP=비연결형/비신뢰성/가벼움`으로 암기한다.

### 15. IP 헤더와 TCP 헤더 구조

**시험 답안**

IPv4 헤더 구조:

```text
버전(4) | 헤더 길이(4) | 서비스 유형(8) | 전체 길이(16)
식별자(16) | 플래그(3) | 단편화 오프셋(13)
TTL(8) | 프로토콜(8) | 헤더 체크섬(16)
송신측 주소(32)
수신측 주소(32)
옵션 및 패딩(가변)
데이터(가변)
```

IP 헤더 필드 설명:
- 버전: IP 버전이다. IPv4는 4.
- 헤더 길이: IP 헤더 길이를 나타낸다.
- 서비스 유형: 우선순위, 지연, 신뢰도 등 QoS 관련 정보다.
- 전체 길이: 헤더와 데이터를 포함한 전체 길이다.
- 식별자: 단편화된 패킷을 다시 합칠 때 사용한다.
- 플래그: 단편화 가능 여부와 뒤에 단편이 더 있는지 표시한다.
- 단편화 오프셋: 나뉜 패킷의 원래 위치다.
- TTL: 라우터를 지날 때마다 감소하고 0이면 폐기된다.
- 프로토콜: 상위 계층 프로토콜이다. TCP=6, UDP=17, ICMP=1.
- 헤더 체크섬: 헤더 오류를 검사한다.
- 송신측/수신측 주소: 출발지와 목적지 IP 주소다.
- 옵션 및 패딩: 선택 기능과 32비트 정렬을 위한 필드다.

TCP 헤더 구조:

```text
송신 포트(16) | 수신 포트(16)
순서 번호 Sequence Number(32)
확인응답 번호 ACK Number(32)
헤더 길이(4) | 예약(6) | 코드 비트(6) | 윈도우 크기(16)
체크섬(16) | 긴급 포인터(16)
옵션 및 패딩(32비트 배수)
데이터(가변)
```

TCP 헤더 필드 설명:
- 송신/수신 포트: 응용 프로그램을 구분한다.
- 순서 번호: 전송 데이터의 순서를 나타낸다.
- 확인응답 번호: 다음에 받을 번호이며 ACK 비트가 1일 때 유효하다.
- 헤더 길이: TCP 헤더 길이다.
- 예약: 확장을 위해 남겨둔 필드다.
- 코드 비트: U, A, P, R, S, F로 긴급/ACK/Push/Reset/SYN/FIN을 나타낸다.
- 윈도우 크기: 수신측 버퍼 크기를 알려 흐름제어에 사용한다.
- 체크섬: 헤더와 데이터 오류를 검사한다.
- 긴급 포인터: 긴급 데이터 위치를 나타낸다.
- 옵션 및 패딩: MSS 등 선택 정보를 담고 32비트 배수를 맞춘다.

**해설**

이 문항은 수시시험 10점이라고 적혀 있어 최우선 암기 대상이다. 빈칸형으로 나오면 필드명과 비트 수가 중요하다. 특히 IP는 `단편화 3종 세트 = 식별자/플래그/오프셋`, TCP는 `순서 번호/ACK 번호/윈도우/코드 비트`를 확실히 외운다.

### 16. ARP와 RARP 비교

**시험 답안**

ARP는 IP 주소를 MAC 주소로 변환하는 프로토콜이다. 같은 LAN에서 상대의 IP 주소는 알고 있지만 MAC 주소를 모를 때 ARP Request를 브로드캐스트하면 해당 호스트가 ARP Response로 자신의 MAC 주소를 알려준다.

RARP는 MAC 주소를 IP 주소로 변환하는 프로토콜이다. 자신의 MAC 주소만 알고 IP 주소를 모르는 장치가 RARP 서버에 요청하면 서버가 IP 주소를 알려준다. 요즘은 DHCP가 이 역할을 대부분 대체한다.

즉 ARP는 `IP -> MAC`, RARP는 `MAC -> IP`이다.

**해설**

이름 때문에 헷갈리기 쉽지만 `R`은 Reverse다. ARP의 방향을 먼저 외우고, RARP는 그 반대라고 쓰면 된다.

### 17. IPv6 특징 및 장점

**시험 답안**

IPv6는 IPv4의 주소 부족 문제를 해결하기 위해 주소 길이를 32비트에서 128비트로 확장한 인터넷 프로토콜이다.

주요 특징과 장점:
- 주소 공간 확장: 128비트 주소로 주소 고갈 문제를 해결한다.
- 헤더 단순화: 잘 쓰지 않는 필드를 확장 헤더로 분리해 라우터 처리가 빠르다.
- 보안 강화: IPSec 기반 인증과 암호화를 지원한다.
- QoS 지원: 흐름 레이블로 실시간 트래픽 처리를 지원한다.
- 자동 구성: 주소 자동 설정을 지원한다.
- 유니캐스트, 멀티캐스트, 애니캐스트를 지원한다.

**해설**

가장 큰 장점은 주소 공간 확장이다. 나머지는 헤더 단순화, 보안, QoS, 자동 구성 순서로 외우면 된다.

### 18. RIP와 OSPF 비교

**시험 답안**

RIP와 OSPF는 모두 자율 시스템 내부에서 경로를 정하는 내부 라우팅 프로토콜 IGP이다.

| 구분 | RIP | OSPF |
|---|---|---|
| 방식 | 거리 벡터 | 링크 상태 |
| 기준 | 홉 수 | 비용, 대역폭 |
| 규모 | 소규모, 최대 15홉 | 대규모, 영역 개념 사용 |
| 갱신 | 30초마다 전체 라우팅 정보 전송 | 변화 발생 시 빠르게 알림 |
| 특징 | 단순하지만 확장성 낮음 | 복잡하지만 빠르고 대규모에 적합 |

**해설**

RIP는 단순, OSPF는 정교하다. `거리 벡터/홉 수/15홉`과 `링크 상태/비용/대규모`를 짝으로 외운다.

| 1 | X.25 | 패킷 교환망에서 쓰는 가상회선 기반 표준 프로토콜 | 오류/흐름 제어가 강하지만 오버헤드가 큼 |
| 2 | 플러딩 | 들어온 패킷을 수신 포트만 제외하고 모든 포트로 내보내는 방식 | 경로를 몰라도 전달 가능하지만 트래픽 증가 |
| 3 | 마스크 | IP 주소에서 네트워크부와 호스트부를 구분하는 32비트 값 | 1은 네트워크, 0은 호스트 |
| 4 | ICMP | IP 오류나 상태 메시지를 알려주는 네트워크 계층 프로토콜 | ping, 목적지 도달 불가, 시간 초과 |
| 5 | IGMP | 호스트의 멀티캐스트 그룹 가입/탈퇴를 라우터에 알리는 프로토콜 | 그룹 관리 |
| 6 | TELNET | 원격 서버에 접속해 명령을 실행하는 원격 로그인 프로토콜 | 23번 포트, 암호화 없어 보안 약함 |
| 7 | FTP | 파일 전송 프로토콜 | 제어 21번, 데이터 20번 연결 |
| 8 | SNMP | 네트워크 장비 상태를 감시/관리하는 프로토콜 | UDP, MIB, 에이전트 |
| 9 | SMTP | 전자우편을 송신하는 프로토콜 | 25번 포트, 수신은 POP3/IMAP |
| 10 | DNS | 도메인 이름을 IP 주소로 바꾸는 시스템 | 문자 주소와 숫자 주소 연결 |
| 11 | FDDI | 광섬유 기반 이중 토큰링 방식 100Mbps 고속 LAN/백본 규격 | Fiber Distributed Data Interface |
| 12 | DQDB | 이중 버스 구조의 분산 큐 방식 MAN 규격 | IEEE 802.6 |

## 6장 네트워크 구성 장비

| 장비 | 계층 | 핵심 기능 | 암기 포인트 |
|---|---:|---|---|
| 트랜시버 | 물리 | LAN에 시스템을 추가하기 위해 전송매체를 분기 | SPT, MPT |
| 리피터 | 물리 | 약해진 디지털 신호를 재생, 중계 | 세그먼트 연장 |
| 허브 | 물리 | 여러 컴퓨터를 연결하고 수신 신호를 포트로 전달 | 더미 허브는 충돌 증가 |
| 브리지 | 데이터링크 | MAC 주소를 보고 세그먼트 간 프레임 전달 여부 판단 | 학습, 플러딩, 포워딩, 필터링, 에이징 |
| 스위치 | 데이터링크 | 다중 포트 브리지처럼 목적지 포트로만 전달 | 충돌 도메인 분리 |
| 라우터 | 네트워크 | 서로 다른 LAN/네트워크 연결, 경로 선택 | IP 기반 라우팅 |
| 게이트웨이 | 상위 계층 | 서로 다른 프로토콜/기종 간 변환 | 프로토콜 변환 |

브리지/스위치 기능:
- 러닝: 출발지 MAC 주소를 보고 MAC 주소 테이블을 만든다.
- 플러딩: 목적지 MAC 주소를 모르면 수신 포트를 제외한 포트로 전송한다.
- 포워딩: 목적지 포트가 테이블에 있으면 그 포트로 보낸다.
- 필터링: 같은 세그먼트 안의 프레임은 다른 세그먼트로 넘기지 않는다.
- 에이징: 오래된 MAC 주소 정보를 삭제한다.

## 7장 교환기술

회선교환:
- 통신 전에 회선을 설정하고, 데이터 전송 후 회선을 해제한다.
- 경로가 고정되어 전용선처럼 사용한다.
- 장점: 전송 중 오버헤드가 작고 연속적인 대용량 전송에 유리하다.
- 단점: 회선 설정 지연이 있고, 회선 설정 뒤 사용하지 않는 시간에도 자원이 낭비된다.
- 대표 예: 전화망

패킷교환:
- 데이터를 패킷으로 나누어 패킷 교환기를 통해 전송한다.
- 물리 회선을 독점하지 않아 사용자 수 제한이 상대적으로 작다.

| 구분 | 데이터그램 | 가상회선 |
|---|---|---|
| 경로 설정 | 사전 설정 없음 | 전송 전 논리 경로 설정 |
| 패킷 처리 | 각 패킷 독립 처리 | 같은 가상회선을 따라 순차 전송 |
| 순서 | 순서가 바뀔 수 있음 | 순서 유지 |
| 장점 | 장애 우회와 짧은 전송에 유리 | 흐름/오류 제어와 순차 전송에 유리 |
| 단점 | 헤더 오버헤드, 재조립 필요 | 설정 지연, 경로 장애 영향 |
| 예 | 인터넷 IP 방식 | X.25의 SVC/PVC |

라우팅:
- 목적지까지 가는 경로를 선택하는 과정이다.
- 평가 기준: 지연시간, 비용, 정확성, 단순성, 견고성, 안정성, 공평성, 최적성
- 비적응 라우팅: 네트워크 상태 변화와 무관하게 경로를 정한다. 예: 고정 경로 배정
- 적응 라우팅: 트래픽과 장애 상태에 따라 경로를 바꾼다. 예: 중앙 집중, 분산, 고립, 델타 적응
- 플러딩: 들어온 패킷을 수신 링크를 제외한 모든 출력 링크로 내보내는 방식이다.

X.25:
- ITU-T가 권고한 패킷 교환망 표준 프로토콜이다.
- 계층: 물리계층, 링크계층, 패킷계층
- 가상회선 방식: SVC는 필요할 때 설정/해제, PVC는 고정적으로 준비된 가상회선
- VCI는 가상 채널을 구분하는 식별자다.
- 데이터 패킷과 제어 패킷을 사용한다.

## 8장 TCP/IP

TCP/IP 4계층과 OSI 비교:

| TCP/IP | 주요 역할 | 관련 OSI 계층 | 대표 프로토콜 |
|---|---|---|---|
| 응용 | 사용자 서비스 | 응용, 표현, 세션 | TELNET, FTP, SNMP, SMTP, DNS |
| 전송 | 종단 간 통신 | 전송 | TCP, UDP |
| 인터넷 | 주소 지정, 라우팅 | 네트워크 | IP, ARP, RARP, ICMP, IGMP |
| 네트워크 접근 | 물리 매체 접근 | 데이터링크, 물리 | Ethernet, LAN 관련 |

인터넷을 위한 주소 3종류:
- 물리 주소: MAC 주소. 데이터링크 계층에서 사용하며 NIC에 저장된다.
- IP 주소: 네트워크 계층의 논리 주소. 호스트와 네트워크를 식별하고 라우팅에 사용된다.
- 도메인 이름: 사람이 읽기 쉬운 이름. DNS가 IP 주소로 변환한다.

IP 클래스:

| 클래스 | 첫 옥텟 범위 | 용도 |
|---|---:|---|
| A | 1~126 | 대규모 네트워크 |
| B | 128~191 | 중규모 네트워크 |
| C | 192~223 | 소규모 네트워크 |
| D | 224~239 | 멀티캐스트 |
| E | 240~255 | 예약/실험용 |

IP 헤더 빈칸 대비:
- Version: IP 버전
- Header Length: 헤더 길이
- Type of Service/Service: 서비스 품질 관련
- Total Length: 전체 데이터그램 길이
- Identification, Flags, Fragment Offset: 단편화와 재조립
- TTL: 라우터를 지날 때 감소, 0이면 폐기
- Protocol: 상위 프로토콜 식별
- Header Checksum: 헤더 오류 검사
- Source/Destination Address: 송신지/수신지 IP 주소
- Options/Padding: 선택 기능과 패딩

ARP/RARP:
- ARP: IP 주소를 알고 있을 때 MAC 주소를 찾는다.
- RARP: MAC 주소를 알고 있을 때 IP 주소를 찾는다.

ICMP/IGMP:
- ICMP: IP 전달 오류와 네트워크 문제를 알리는 제어 메시지 프로토콜이다.
- IGMP: 멀티캐스트 그룹 가입/관리를 위한 프로토콜이다.

RIP/OSPF:

| 구분 | RIP | OSPF |
|---|---|---|
| 유형 | 거리 벡터 | 링크 상태 |
| 기준 | 홉 수 | 비용 |
| 알고리즘 | Bellman-Ford 계열 | Dijkstra SPF |
| 특징 | 단순하지만 대규모망에 약함 | 수렴이 빠르고 대규모망에 적합 |
| 제한 | 최대 15홉 | 영역 기반 운영 가능 |

IPv6 특징:
- 주소 길이가 32비트에서 128비트로 확장된다.
- 헤더 구조가 단순화된다.
- 확장 헤더를 사용한다.
- 흐름 레이블 등 QoS 처리가 개선된다.
- 보안 기능이 강화된다.

TCP/UDP:

| 구분 | TCP | UDP |
|---|---|---|
| 연결 | 연결형 | 비연결형 |
| 신뢰성 | ACK, 순서 제어, 오류/흐름 제어 | 보장하지 않음 |
| 헤더 | 비교적 큼 | 8바이트 |
| 용도 | 파일전송, 웹, 메일처럼 신뢰성 필요 | 실시간, 단순 질의, 오버헤드 최소 |

응용 프로토콜:
- TELNET: 원격 로그인
- FTP: 파일 전송. 제어 연결 21번, 데이터 연결 20번
- SNMP: 네트워크 관리. UDP 사용
- SMTP: 전자우편 전송
- DNS: 도메인 이름과 IP 주소 변환

## 9장 고속/광역 데이터 서비스

FDDI:
- Fiber Distributed Data Interface
- 광섬유 기반 고속 LAN/MAN 기술이다.
- 토큰 링과 유사하게 동작하고 이중 링 구조를 사용한다.
- DAS, SAS, DAC, SAC 같은 접속 형태가 나온다.
- SMT는 스테이션 추가/제거, 장애 탐지, 링 재구성을 담당한다.

DQDB:
- Distributed Queue Dual Bus
- IEEE 802.6 계열 MAN 기술이다.
- 두 개의 단방향 버스를 사용하고 분산 큐 방식으로 접근을 제어한다.

SMDS:
- Switched Multimegabit Data Service
- 고속 교환 데이터 서비스다.
- SNI는 사용자와 네트워크 사이, ISSI는 교환기 사이, ICI는 다른 사업자/외부 네트워크와의 인터페이스다.

프레임 릴레이:
- 패킷 교환 기반의 고속 WAN 기술이다.
- 에러/흐름 제어를 단순화하여 고속 전송을 지향한다.
- DLCI는 가상 연결을 식별한다.
- FECN은 전방향 혼잡 알림, BECN은 역방향 혼잡 알림, DE는 폐기 가능 비트다.
- 프레임 필드: Flag, Address, Data, FCS
