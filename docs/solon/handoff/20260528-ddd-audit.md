## 2. 리팩토링 Slice 제안

### Slice 1 (P1) — Repository 패턴 도입

- 목표: Prisma 직접 노출 제거.
- 작업:
  - `packages/persistence` 또는 `apps/api/src/<domain>/repositories/` 에 interface 정의: `PdfMaterialRepository`, `SubjectRepository`, `TermRepository`, `AnnotationRepository`, `UserRepository`.
  - Prisma 구현체 = `PrismaPdfMaterialRepository` 등 (현재 service 안 query 이동).
  - service 가 repo 만 의존.
  - test = repo mock.
- 예상: 2 주. 모든 service 동시 수정.

### Slice 2 (P1) — God Service 해체

- 목표: `MaterialsService` 책임 분할.
- 작업:
  - `MaterialUploadService` ← `createUploadIntent`, `uploadFile`, `completeUpload`.
  - `AnnotationService` ← `saveAnnotation`, `getAnnotation`, `listAnnotations`.
  - `PdfMaterialQueryService` ← find / access control.
- 의존: Slice 1 (repository).
- 예상: 2 주.

### Slice 3 (P1) — Domain model 강화

- 목표: Anemic → Rich.
- 작업:
  - `StudyNotebook`, `SubjectNote` class 정의 (interface → class).
  - `getIntegrityWarnings()` / `getSubjectCoverage()` → instance method.
  - `DateProvider` port 도입 + `pdf-workspace.ts` 의 `Date.now()` 5 곳 주입.
  - `console.warn` 제거 (validation result type).
- 예상: 1 주.

### Slice 4 (P2) — Bounded Context 분리

- 목표: Term ↔ Subject ↔ Material 경계 명확.
- 작업:
  - `TermHierarchyPolicy`, `SubjectsPolicy` port.
  - `ensureTermHierarchyAllowed()` 이동.
  - 자신의 aggregate 만 mutate, 외부 = query.
- 예상: 1.5 주.
