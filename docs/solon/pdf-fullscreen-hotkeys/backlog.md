# PDF 전체화면 + 필기도구 단축키

## 1. 목표

PDF 학습 화면에서 두 가지 사용성 개선:

1. **PDF 전체화면 모드** — 사이드바/툴바 접고 PDF + annotation layer 를 화면
   전체에 키워서, 강의 중 받아쓰기/필기에 집중할 수 있게 한다.
2. **필기도구 단축키** — 현재 마우스로만 전환 가능한 도구
   (읽기 / 포스트잇 / 펜 / 지우개 / 텍스트 박스 / 체크리스트 / 표 / 그래프)
   를 키보드 단축키로 즉시 전환할 수 있게 한다. 동시에 **각 버튼 라벨에
   단축키를 함께 표시** 해 학습 부담을 없앤다.

## 2. 사용자 요구 (raw)

> "PDF 전체화면 및 필기도구 단축키 추가 (추가시 단축키 같이 표시해줘서
> 사용자가 바로 쓸 수 있도록)"

핵심: 발견 가능성 (discoverability) 을 단축키 노출로 보장한다.

## 3. 범위 후보 (브레인스토밍용 — `/sfs brainstorm` 에서 확정)

### 3.1 전체화면

- 트리거 후보:
  - 툴바에 "전체화면" 버튼 추가 + 단축키 (e.g. `F`).
  - 브라우저 Fullscreen API (`element.requestFullscreen()`) 사용 여부.
  - 또는 in-app "집중 모드" (사이드바 + 헤더만 숨김, 브라우저 chrome 유지).
- ESC 또는 같은 키로 복귀.
- 풀스크린 상태에서도 페이지 이동/도구 전환 단축키 동작해야 함.

### 3.2 단축키 매핑 (제안 — 확정은 brainstorm)

| 키 | 동작 |
|:--|:--|
| `R` | 읽기 (read-only) |
| `P` | 펜 |
| `E` | 지우개 |
| `N` | 포스트잇 (note) |
| `T` | 텍스트 박스 |
| `C` | 체크리스트 |
| `B` | 표 (table) |
| `G` | 그래프 |
| `F` | 전체화면 토글 |
| `←` / `→` | 이전 / 다음 페이지 |
| `?` | 단축키 도움말 오버레이 |

원칙:
- 입력 포커스가 텍스트 박스/포스트잇/체크리스트 등 편집 가능 영역에 있을
  때는 단축키를 **비활성화** 한다 (typing collision 방지).
- 한/영 전환 무관하게 동작하도록 `event.code` 기반 dispatch.

### 3.3 단축키 표시

- 각 도구 버튼 라벨에 키 배지를 같이 렌더링.
  - 예: `읽기 R` / `펜 P` / `지우개 E` 식으로 chip 형태.
- 모바일/터치 환경에서는 배지를 숨긴다 (단축키 의미 없음).
- `?` 키로 띄우는 modal 오버레이에서 전체 단축키 표 노출.

## 4. Out of scope (다른 사이클)

- 사용자별 단축키 커스터마이즈.
- 멀티 키 시퀀스 (Vim-like) — 단일 키만.
- 매크로 / 텍스트 스니펫.

## 5. 검증 기준 (Acceptance — 초안)

- 모든 도구가 단축키로 전환 가능하고, 버튼 라벨에 단축키가 시각적으로 노출된다.
- 텍스트 박스에 타이핑 중일 때 단축키가 도구를 바꾸지 않는다.
- `F` 로 전체화면 진입/복귀가 데스크톱 Chrome/Firefox/Safari 에서 동작한다.
- `?` 로 단축키 도움말이 열리고, 같은 키로 닫힌다.
- 모바일 (≤ 480px) 에서 배지가 숨겨지고 레이아웃이 깨지지 않는다.
